# P-43 ✂️ (다듬기) 출석부에서 「내 이름」 바로 찾기
- 상태: 제안 (2026-11-10 · 기존 칸 다듬기 · 코드 확인함)
- 종류: **기존 칸 다듬기** (새 데이터 없음)
- 한 줄: 주간스쿼드 아래 접힌 「📋 이번 주 출석부」는 협곡 참가자 전원(제6호 87명)이 **가나다·판수 순서 없이 한 덩어리**로 나와요. 내 이름을 찾으려면 스크롤해야 해서, 디스코드로 로그인한 사람은 내 줄을 맨 위에 올려 강조하고 누구든 이름 검색 칸으로 바로 찾게 해요.
- 누구를 위해: 주간스쿼드를 읽는 클랜원 전원 — 출석부는 「내가 이번 주 이름이 나왔나」 확인하는 칸이라 찾는 데 걸리는 시간이 곧 만족도.
- 근거(index.html `_npRoster` 5780행 부근 · 2026-11-10 코드 확인):
  - 출석부는 `<details>` 안에 `np-roster-grid` 로 **이름·판·승·한 줄 사실**을 봇이 준 순서대로 모두 나열(최대 250명까지). 제6호 기준 87명 → 폰 한 열이면 수 화면 길이.
  - 로그인 상태(내 이름)를 읽어 강조·정렬하는 코드는 없다. 검색 입력도 없다. 반응 버튼(P-29/P-39)은 이미 로그인 상태를 읽고 있어 같은 값을 쓸 수 있다.
  - 이 칸이 「이름이 불리는」 기쁨의 자리라(10/21 P-27 취지) 내 줄이 눈에 띄면 효과가 크다.
- 무엇을: 1) 로그인한 사람의 이름이 출석부에 있으면 맨 위에 「⭐ 내 줄」로 따로 올리고 배경 강조 2) 펼침 안에 이름 검색 한 칸(입력하면 목록 거름) 3) 정렬은 바꾸지 않는다(봇이 준 순서 유지). 이름 검증·`esc` 규칙 그대로.
- 위험·되돌리기: 이름 일치는 LINK 그룹(본계/부계)을 고려해야 해서 화면의 `linkComponents`/대표닉 규칙을 재사용(새로 만들지 않음). 일치 실패 시 강조 없이 지금과 같음. 블록 하나라 지우면 원복. 모델·봇·시트 변경 없음.
- 성공 지표: 폰 360px 출석부 펼침 후 내 줄 도달까지 스크롤 0화면 · 가로 넘침 0 · 디스코드 반응.
