# P-27 📋 이번 주 출석부 — 주간스쿼드에 뛴 사람 전원의 이름 한 줄씩
- 상태: 제안 (2026-10-18 기획 회의 18점 후보 · 10/21 지면 보관본으로 직접 재확인)
- 한 줄: 주간스쿼드는 매주 협곡 80~100명이 뛰는데 이름이 실리는 사람은 15명 안팎이에요. 지면 맨 아래에 그 주 뛴 사람 전원의 이름·판수·승패·눈에 띈 사실 한 줄을 접힌 「출석부」로 붙여서, 누구든 자기 이름을 지면에서 찾을 수 있게 해요.
- 누구를 위해: 주간 협곡 참가자 약 81~106명. 지금은 호당 14~16명만 이름이 실린다.
- 왜 지금(2026-10-21 `data/weekly_archive/` 1~5호 직접 계산):
  - **이름이 실린 사람**(인물란 `students` + 상 `awards`): 1호 15명 · 2호 16명 · 3호 15명 · 4호 14명 · 5호 16명 = 그 주 참가자 대비 **15~20%**. 5개 호를 합쳐도 서로 다른 이름이 **46명**뿐(회의 계산: 10판↑ 83명은 35%, 3~9판 46명은 4%).
  - 주간스쿼드 독자 반응이 사실상 0(댓글 전 기간 1개, 사장님 본인) — '내 이름이 없는 신문'을 읽을 이유가 적다는 가설과 맞는다. P-22(디스코드 알림, 보류)가 '알리는 쪽'이라면 이 안은 '읽을 이유를 만드는 쪽'.
  - 지면 사실은 전부 상위 2~3명 목록(`facts`) — 중위권·새내기는 어느 칸에도 안 나온다.
- 무엇을:
  1. 봇 `_weekly_push` 가 **모델을 거치지 않고** 참가자 전원의 {닉, 판, 승, 패, 사실 한 줄}을 결정론적으로 만들어 `weekly_review.json` 의 `roster` 필드에 넣는다.
  2. 사실 한 줄은 규칙 하나만 고른다 — 우선순위: 개인 최다 킬 갱신 → 7연승 → 첫 챔프(P-17 계산 재사용) → 가장 늦게 뛴 사람(심야 판수) → 없으면 '이번 주 N판'. **나쁜 기록(0승 3패·7연패)은 실리지 않게** 규칙에서 뺀다.
  3. 웹 `newsPageHtml` 이 접힌 「📋 출석부 (95명)」 한 칸을 그린다 — 이름은 `esc` 후 프로필(P-23 `#p/닉`) 링크.
  4. 모델의 이름 화이트리스트 규칙은 그대로. LINK 그룹·PUUID 로 사람 단위 묶기(닉변·부계 중복 방지), 손님(명단 밖)·스크림 판 제외(A-20 규칙 재사용).
  - **필드명이 늘므로 CLAUDE.md 규칙대로 봇·프롬프트·웹 세 곳을 같은 커밋에서** 고친다(프롬프트는 `roster` 를 모델에 안 넘긴다는 한 줄).
- 이미 있는 것과의 관계: 주간스쿼드 인물란·상(상위권만) · P-22 디스코드 알림 · 웹 프로필(P-23) · 내전 기록실. 출석부는 지면의 **이름 커버리지**를 넓히는 안.
- 시제품: 접힌 칸 문구
  ```
  📋 이번 주 출석부 (81명) — 누르면 펼쳐져요
  허거덩 49판 26승 · 한 판 27킬  /  RayB 48판 · 서폿 28판  /  규돌이 11판 · 7연승 …
  ```
  승인되면 지난주 보관본(10/18)으로 만든 `lab/P-27.html` 미리보기부터.
- 만드는 순서: 1) 봇 `roster` 계산 + 시험(5호 재생: 81명·손님/스크림 제외·나쁜 기록 0) (S~M) 2) 웹 접힌 칸 + 프로필 링크(S) 3) 첫 2호는 사장님 확인 뒤 정식 4) 2주 뒤 재측정.
- 위험·되돌리기: 닉변·부계가 따로 한 줄씩 나오거나 손님 이름이 실리면 곤란 → LINK·손님 제외 필수. 사실 한 줄에 나쁜 기록이 실리지 않게 규칙 고정. 지면이 길어져 폰에서 느려지면 접힌 칸만 지연 렌더. 새 필드라 옛 보관본에는 없음(웹이 없으면 칸 숨김). 필드 하나 지우면 원복.
- 성공 지표: 지면에 이름이 실린 비율(지금 15~20% → 95%+ · 출석부 기준) · 주간스쿼드 댓글 수(지금 전 기간 1개) · P-26 계기판이 있다면 #news 열람.
