# P-26 📏 기능 사용 계기판 — 만든 웹 기능이 쓰이는지 숫자로 보이게
- 상태: 제안
- 한 줄: 지금은 웹 화면(홈 카드·프로필 칸·탭)이 **몇 명에게 열렸는지 아는 방법이 없어서** 만든 기능이 먹혔는지 판정을 못 해요. 사람 없이 "기능 이름별 하루 열림 횟수" 만 세는 익명 계기판을 봇 `/health` 에 두고, 웹이 화면을 열 때 한 줄 신호만 보내요.
- 누구를 위해: 사장님(승인한 기획이 쓰였는지 보고 싶을 때) · 루프(효과 확인). 클랜원에게는 보이는 변화 없음.
- 왜 지금(2026-10-20 효과 확인 시도 결과):
  - 출시한 기획안의 효과 확인 6건 중 **판정 가능했던 것은 2건뿐**: P-9 승부예측(노출 286판에 누른 사람 3명 — 서버가 세고 있어서 판정 가능) · P-2 공유 링크(14일간 채팅에 올라온 공유 링크 0건 — 봇이 세고 있음).
  - 나머지는 **세는 곳이 없어 판정 불가**: P-11 이번 패치 카드 · P-12 대기실 전력 차(분석기 화면) · P-14 몇 판째에 강한가 · P-16 하프타임 섞기(지표를 시트로 환산해도 소음에 묻힘 — 아래).
  - P-16 재계산: 직전 판과 10명 중 8명↑ 겹치는 비율 8/1~10/6 51.6%, 10/7 기본 켜짐 이후 56.2%(주별 58.0%·54.4%) — 줄지 않았지만 제안이 실제로 뜬 횟수·눌린 횟수를 모르니 원인을 못 가린다.
  - 같은 기능(웹 첫 화면 접이식 카드 등)이 앞으로도 계속 늘어난다(P-19·P-21·P-24·P-25 대기 중) — 매번 "쓰였는지 모름" 으로 끝나면 승인·보류 판단 근거가 없다.
- 무엇을:
  1. 웹: 화면(탭·카드·프로필 탭)을 열 때 `POST /m/hit {k:"profile.tab.rec"}` 한 줄(기능 이름만 · 닉·id·토큰 없음). 하루 1회 방문당 1번만(같은 기기에서 중복 방지는 localStorage 날짜 키).
  2. 봇: 이름 화이트리스트(모르는 키는 버림) · 일별 합계 파일 90일 보관 · IP 상한(기존 `_p6` IP 제한 재사용) · `/health` 의 `usage` 에 최근 7·14일 합계.
  3. 분석기/봇 쪽 기능(P-12 맞바꾸기 제안·P-16 하프타임 제안/클릭)도 같은 방식으로 봇에 기록(이미 봇이 아는 것은 카운터만 추가).
  4. 루프 `signals.py` 가 `usage` 를 읽어 효과 확인 때 자동으로 숫자를 적는다.
- 이미 있는 것과의 관계: 봇 `links`(채팅 공유 링크 수) · `pred`(승부예측 노출·클릭·누른 사람 해시) · `p6.active`(서바이벌 활동) — 모두 **봇이 이미 보는 곳**의 계기. 웹 화면 열람은 어디에도 없다.
- 시제품: `/health` 예시
  ```
  "usage": {"7d": {"home.shift_card": 41, "prof.tab.rec": 188, "home.tonight": 63, "ach": 120}, "days": 7}
  ```
- 만드는 순서: 1) 봇 `/m/hit` + 파일 + `/health usage`(S) 2) 웹 한 줄 신호(S) 3) signals.py 가 읽기(S) 4) 2주 뒤 기존 P 효과 판정 한 번에.
- 위험·되돌리기: **웹→봇 새 요청**이라 B(사장님 승인) — 개인정보 없음(이름·id 없음, 합계만)이지만 클랜원 접속을 센다는 점을 사장님이 정하실 일. 요청 폭주는 화이트리스트·IP 상한·하루 1회로 막고, 봇 환경변수 한 줄로 끈다. 웹 신호는 실패해도 화면에 영향 없게(fire-and-forget).
- 성공 지표: 출시 2주 뒤 기존 P(P-11·P-14·P-23 등)의 효과 확인 판정 가능 비율 2/6 → 6/6 · 안 쓰이는 기능의 보류·정리 근거.
