# P-32 ⓘ 폰에서도 보이는 지표 뜻풀이 — 마우스를 올려야만 뜨는 설명 살리기
- 상태: **승인(2026-10-26 사장님 「p32진행」) · 제작은 스해분 프로젝트 세션에 전달**(루프는 직접 배포하지 않는다는 사장님 지시 유지 — 이 세션에서 만들라고 하시면 바꿈)
- 한 줄: 프로필·랭킹 지표(견제 압력·내전 활약·팀운·짊어진 무게·부포지션 …)의 **설명문이 마우스를 올려야 뜨는 말풍선(title 속성)에만** 있어 폰에서는 읽을 방법이 없어요. 칸의 ⓘ 를 탭하면 뜻풀이가 아래에서 올라오게 해요. 새 문구를 쓰지 않고 이미 있는 설명을 보이게만 합니다.
- 누구를 위해: 웹 지표를 이해하고 싶은 모든 클랜원 — 폰 사용자·새 클랜원(8/3 이후 합류자). 폰 비율은 접속 기록이 없어 못 쟀고, 터치 화면에는 hover 가 없다는 사실에만 근거(근거 약한 부분).
- 왜 지금(index.html 10/26 직접 확인):
  - `title=` 속성이 **137곳**. 그중 지표 설명(수십~백 자)이 많다 — 예: 견제 압력 '내가 낀 판 밴율 − 내가 없는 판 밴율로 계산해 원래 인기 밴 챔프의 영향을 제거했습니다…'(~130자), 내전 활약 '솔랭을 빼고 내전 기록만으로 매긴 점수. 클랜 평균 50'. 회의 계산: 30자↑ 설명문 44곳 · 60자↑ 공식 설명 11곳.
  - 프로필 지표 칸의 해설은 `cell(k,v,ref,cls,tip)` 이 tip 을 **title 속성에만** 넣는다(프로필 지표 20여 칸 — 부포지션·짊어진 무게·항노화·팀운·멸망전 적정가 등).
  - 탭하면 설명이 뜨는 코드가 없다(grep `data-tip|touchstart|infoPop|tooltip` 0건, `(hover` 미디어쿼리 0건). 반면 뒷심지수 같은 일부 화면은 설명을 본문에 직접 써 둬서 폰에서도 읽힌다 — **같은 사이트 안에서 지표마다 설명이 보이는지가 제각각**.
  - P-20(최근 30일)·P-23(프로필 탭)처럼 폰 사용성 승인이 이어졌고, 사장님이 만든 지표(항노화·억울지수·뒷심 등)는 설명을 읽어야 의미가 있다.
- 무엇을:
  1. 전역 위임 스크립트 하나(~40줄): 터치 기기(`(hover:none)`)에서 `[title]` 요소(설명이 있는 칸의 ⓘ)를 탭하면 title 값을 읽어 화면 아래 작은 시트로 보여 주고, 다시 탭하면 닫는다. 기본 title 은 제거해 이중 표시 방지. **PC 는 지금과 같다.**
  2. 설명이 있는 칸에 점선 밑줄 또는 작은 ⓘ 를 달아 탭할 곳임을 알린다. 이미 `onclick`(이동)이 걸린 칸은 ⓘ 아이콘만 탭 대상으로 삼아 충돌을 피한다.
  3. 처음 노출되는 설명 44곳은 한 번 읽어 사실과 다른 옛 문구가 없는지 점검(패치노트 불필요 수준의 문구 정리).
- 이미 있는 것과의 관계: 뒷심지수 등 일부 본문 설명 · 프로필 `cell()` tip · 랭킹의 title. 새 글 없이 노출만 — P-19(머리 영역)·P-23(프로필 탭)·P-31(기록부)과 겹치지 않는다.
- 시제품: 탭 시트 예시
  ```
  ⚖️ 짊어진 무게 92/100 ⓘ   ← 탭
  ┌ 밸런스 가정에서 판마다 역산한 '매칭이 상정한 내 실력'의 통산 평균을 백분위로 환산 …  [닫기]
  ```
  승인되면 `lab/P-32.html` 에 실제 프로필로 도는 미리보기부터.
- 만드는 순서: 1) 탭 시트 스크립트 + 프로필 지표 칸 ⓘ(웹 · S) 2) 랭킹·기타 title 로 확대(S) 3) 설명문 44곳 점검 정리(S) 4) 2주 뒤 재측정.
- 위험·되돌리기: title 이 걸린 요소에 이미 onclick 이 있는 곳이 많아 충돌 → ⓘ 아이콘만 대상. 옛 설명문에 사실과 다른 문구가 숨어 있을 수 있음 → 3번 점검. 스크립트 한 블록을 지우고 BUILD_ID 를 올리면 원복.
- 성공 지표: 폰 프로필에서 지표 설명을 열어 본 횟수(P-26 계기판이 없으면 측정 불가 — 디스코드 반응·'이 지표가 뭐예요' 제보 수 감소).
